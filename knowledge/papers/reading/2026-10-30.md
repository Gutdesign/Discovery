# Что прочитать — 2026-10-30

Отобрано 8 из 1073 статей первого сбора. Критерии — `knowledge/papers/README.md`. Статьи 1, 4 и 8 проверены по полному тексту (alphaXiv), остальные — по аннотации.

Сквозная тема подборки: проверка проектной документации (чертежи, нормативы, BIM) с помощью мультимодального и графового RAG — то есть ровно то место, где по реестру экспертизы видны боли P13–P15 (повторные и отрицательные заключения, `knowledge/pains.md`).

## 1. Evidence-Grounded Constraint Checking in Construction Documents — RAG × AEC
https://arxiv.org/abs/2607.29058 · 2026-07-31 · arXiv

**Почему читать:** самая трезвая на сегодня оценка того, может ли модель проверять комплект чертежей. 160 задач из 29 реальных проектов: точность решения «соответствует / не соответствует» — 40–55%, ложное «соответствует» — в 41–52% случаев. Вывод авторов: для самостоятельной приёмки непригодно, годится только для сортировки перед экспертом. Это реалистичный потолок для любой идеи «ИИ-предпроверка перед экспертизой».
**Что взять:** четыре исхода вместо двух (соответствует / не соответствует / не хватает данных / неясно) с правилом «неполные данные никогда не дают „соответствует“»; разделение «извлечь факты моделью → проверить правило детерминированно → приложить ссылку на лист и область»; наблюдение, что для мелких выносок нужно увеличение фрагмента, а для сверки документов между собой — охват многих страниц.
**Оговорка:** проверены только PDF; CAD и IFC — лишь заявленный интерфейс. В основном эксперименте всего 6 проектов, на 23 других проектах выигрыш от увеличения фрагментов не подтвердился.

## 2. AEC-Bench: A Multimodal Benchmark for Agentic Systems in AEC — ИИ в AEC
https://arxiv.org/abs/2603.29199 · 2026-03-31 · arXiv + alphaXiv

**Почему читать:** основной открытый набор задач по реальной проектной работе (чтение чертежей, сверка листов, спецификации, документы по закупке). На нём построена статья № 1. Показывает, какие задачи в проектировании уже измеримы.
**Что взять:** перечень типов задач как готовую карту того, где ИИ может помочь проектировщику; методику оценки.
**Оговорка:** авторы — Nomic и Aurecon (поставщик моделей и крупная инженерная компания); задачи англоязычные, нормы не российские.

## 3. DrawingVQA: A Real-World Benchmark for Multi-Depth Visual-Textual Reasoning on Construction Drawings — RAG × AEC, форматы
https://arxiv.org/abs/2607.15418 · 2026-07-16 · arXiv

**Почему читать:** первый набор вопросов экспертов по реальным выпущенным строительным чертежам, с проверкой, насколько ответ зависит от разрешения и от того, видит ли модель картинку или только текст.
**Что взять:** где именно мультимодальные модели ломаются на чертежах (мелкий текст, ссылки между видами, многоступенчатые выводы) — ориентир для оценки любого своего решения.
**Оговорка:** по аннотации; чертежи американские.

## 4. PlanSightRAG: A Visual-First Multimodal RAG for Compliance Checking for Civil Standard Plans — мультимодальный RAG, RAG × AEC
https://arxiv.org/abs/2608.26091 · 2026-08-26 · arXiv + alphaXiv

**Почему читать:** рабочая схема мультимодального RAG прямо по изображениям чертежей, без распознавания текста, которое теряет геометрию. Поиск нужного листа — 91% попаданий в первую пятёрку, в том числе на чужом корпусе. Плюс набор из 4 056 вопросов по типовым чертежам пяти дорожных ведомств США.
**Что взять:** связку «многовекторный поиск по картинкам страниц (ColNomic) + агент планировщик–поисковик–проверяющий–составитель ответа + тепловая карта как след доказательства».
**Оговорка:** честная, но важная: 100% верных вердиктов только когда числовой порог правила уже дан; простой конвейер на распознанном тексте даёт 76%. Самое трудное — само извлечение правила из норматива — показано лишь как демонстрация.

## 5. GEMS-RAG: Graph-grounded Engineering Multimodal Standards RAG — поиск по графам, RAG × AEC
https://arxiv.org/abs/2610.33277 · 2026-10-23 · arXiv + alphaXiv

**Почему читать:** нормативы — иерархия разделов, таблицы, рисунки, перекрёстные ссылки. Статья строит граф именно по такой структуре и ищет по нему. Прямо ложится на работу с СП и ГОСТ.
**Что взять:** как моделировать норматив графом (пункт → таблица → рисунок → ссылка на другой пункт) и как по нему собирать контекст.
**Оговорка:** по аннотации; свежая, без отзывов сообщества.

## 6. IfcLLM: Natural Language Querying of IFC Models through Complementary Relational and Graph Representations — форматы, RAG × AEC
https://arxiv.org/abs/2605.13236 · 2026-05-13 · arXiv + alphaXiv

**Почему читать:** вопросы к IFC-модели обычным языком через два представления сразу — таблицы (SQL) и граф. Ответ на вопрос «как достать данные из BIM для ИИ».
**Что взять:** когда выгоднее запрос к таблицам, когда — обход графа связей элементов; схему преобразования IFC.
**Оговорка:** по аннотации. В пару к ней — IFC-MCQ той же группы (UNSW) как способ проверять такие системы.

## 7. Handoff-H1: Vision-Agent System for Material Quantity Takeoff from Construction Blueprints — RAG × AEC
https://arxiv.org/abs/2608.15032 · 2026-08-15 · alphaXiv

**Почему читать:** подсчёт объёмов материалов по комплекту чертежей — задача, за которую платят (сметы, тендеры). Многоагентная система со зрением, многоступенчатыми выводами по листам и опорой на строительные соглашения, которых нет на чертежах.
**Что взять:** разбиение задачи на агентов; какие неявные знания пришлось закладывать.
**Оговорка:** статья компании-разработчика (Handoff AI) — это заявление поставщика, доказательность не выше C; по аннотации.

## 8. When Is Graph Structure Worth Its Cost? The Case for Structure Pricing in RAG — поиск по графам
https://arxiv.org/abs/2609.18099 · 2026-09-16 · arXiv

**Почему читать:** противовес моде на графовый RAG. Граф используется только чтобы найти нужные куски, а ответ строится по исходному тексту — и это лучше LightRAG в 93 из 120 вопросов при стоимости на 57% ниже. Простые BM25 и обычный RAG ещё в 3 раза дешевле, но хуже.
**Что взять:** правило «граф — указатель, источник — доказательство»; привычку считать стоимость построения графа вместе с качеством.
**Оговорка:** 120 вопросов, сгенерированных моделью, оценка моделью-судьёй, корпуса маленькие (5–20 документов на область).
